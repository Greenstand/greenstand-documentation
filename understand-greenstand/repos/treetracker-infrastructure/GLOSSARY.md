## Domains

### Cloud & Cluster Provisioning

Provisions the foundational cloud substrate with Terraform: DigitalOcean Kubernetes (DOKS) clusters and node pools, AWS/DigitalOcean IAM access, DNS, the bastion host and remote state backends. Also manages Bitnami Sealed Secrets so credentials live safely in git before workloads deploy.

**Terms:** DOKS cluster, node pool, IAM user, bastion, Sealed Secret, remote state backend

**Rules:**

- All state stored in S3-compatible DigitalOcean Spaces backends
- Node pools segregate microservices, cloud-services and monitoring workloads
- Credentials committed to git only as kubeseal-encrypted SealedSecrets

**Flows:**

- **Provision DOKS Cluster** (`terraform apply (kubernetes/terraform)`): Terraform provisions a DigitalOcean Kubernetes cluster with dedicated microservices, cloud-services and monitoring node pools per environment.
- **Provision Cloud Access, DNS & Bastion** (`terraform apply (aws_access, bastion)`): Terraform provisions scoped AWS/DigitalOcean IAM users and access keys, DNS records and the bastion host used to reach private resources.
- **Manage Sealed Secrets** (`create-secret.sh`): Encrypts Kubernetes credentials with kubeseal so they can be committed to git, and deploys the Sealed Secrets controller and web UI.

### Database Platform

Provisions and governs the managed PostgreSQL data tier for the treetracker microservices: the DigitalOcean managed cluster with read replica, per-microservice schemas with least-privilege role grants, pgpool routing and S3 backup storage.

**Terms:** Managed Postgres cluster, microservice schema, role, grant, default privilege, backup bucket

**Rules:**

- Fifteen per-microservice schemas each instantiated from the shared microservice_schema module
- Roles receive least-privilege grants and default privileges per schema
- Firewall rules restrict database access to trusted sources

**Flows:**

- **Provision Managed Postgres** (`terraform apply (database/terraform)`): Terraform provisions the DigitalOcean managed PostgreSQL cluster, its databases, read replica and firewall rules.
- **Provision Schema & Grants** (`terraform apply (database-grants)`): Fans out to per-microservice schemas via the reusable microservice_schema module, creating roles and least-privilege table and default privilege grants.
- **Database Backup Storage** (`terraform apply (database-backup-storage)`): Provisions the backup IAM user and S3-compatible bucket used to store managed PostgreSQL backups.

### Ingress & Identity

Exposes backend services through the Ambassador API gateway and authenticates users with the Keycloak identity provider. Ambassador is the single ingress fronting every service; Keycloak runs a custom-themed image with realm and client configuration.

**Terms:** Ambassador Mapping, ingress host, Keycloak realm, client, custom theme, SealedSecret

**Rules:**

- Ambassador is the single ingress fronting every backend service
- Keycloak credentials injected from SealedSecrets and stored in the keycloak Postgres schema
- Service routes declared as Ambassador Mapping custom resources

**Flows:**

- **Deploy API Gateway** (`ambassador-playbook.yml`): Installs the Ambassador API gateway via an Ansible/Helm playbook, provisions its DNS and applies service Mappings.
- **Deploy Keycloak Identity** (`keycloak/deploy.sh`): Builds the custom-themed Keycloak image and deploys it to Kubernetes with a Kustomize overlay, sealed credentials and an Ambassador route.

### Application & Data Platform

Deploys the higher-level application workloads on the cluster: RabbitMQ messaging, Airflow workflow orchestration, the Solr/CKAN/OpenProject data platform and the S3-backed static web apps with CDN delivery.

**Terms:** RabbitmqCluster, Airflow DAG, Solr Helm release, CKAN portal, static website, CDN images api

**Rules:**

- Async service communication runs on a 3-replica RabbitMQ cluster
- Airflow and CKAN connect to the managed PostgreSQL databases
- Static sites are S3-backed and fronted by CloudFront

**Flows:**

- **Deploy Messaging (RabbitMQ)** (`rabbitmq/deployment/deploy-test.sh`): Deploys a 3-replica RabbitmqCluster via the RabbitMQ Operator using Kustomize overlays per environment.
- **Deploy Workflow Orchestration (Airflow)** (`airflow/airflow-playbook.yml`): Installs Airflow on the DOKS cluster via an Ansible-driven Helm chart with per-environment Postgres connection settings.
- **Deploy Data Platform (Solr/CKAN/OpenProject)** (`terraform apply / kubectl apply`): Deploys the Solr search engine, CKAN open-data portal and OpenProject onto the cluster with external Postgres wiring.
- **Deploy Static Web Apps & CDN** (`terraform apply (web-apps)`): Provisions S3-backed static front-end sites (web map, wallet, admin panels) across environments and the CDN images API via Terraform.

### Observability & Alerting

Observes the platform with a Prometheus/Grafana metrics stack, Loki log aggregation and Jaeger distributed tracing, all installed via Ansible playbooks, plus Botkube chat-ops alerting.

**Terms:** Prometheus Operator, Grafana, Loki, Promtail, Jaeger, node_exporter

**Rules:**

- Metrics, logs and traces installed via Ansible-driven Helm charts
- Ambassador emits zipkin-format traces to the Jaeger collector
- node_exporter runs on all server hosts

**Flows:**

- **Deploy Metrics Stack** (`prom-operator-playbook.yml`): Installs the kube-prometheus-stack (Prometheus, Grafana, Alertmanager) and node_exporter via Ansible.
- **Deploy Logging (Loki)** (`loki role`): Installs the Loki logging stack with Promtail and Fluent-bit via Ansible and Helm.
- **Deploy Tracing (Jaeger)** (`tracing playbook`): Deploys Jaeger distributed tracing and wires the Ambassador gateway to emit zipkin traces.

### Platform Operations & CI

Day-to-day operations and continuous integration: shell scripts to authenticate to the DOKS clusters, provision tooling and export credentials, plus pre-commit and GitHub Actions CI that enforce Terraform formatting.

**Terms:** operator script, doctl kubeconfig, pre-commit hook, GitHub Actions workflow

**Rules:**

- Operators authenticate to each DOKS cluster with doctl and helm
- terraform_fmt runs on every commit via pre-commit
- CI runs pre-commit on pull requests and pushes to master

**Flows:**

- **Cluster Access Setup** (`scripts/doctl_setup.sh`): Operator scripts authenticate to DigitalOcean, save the kubeconfig for a target cluster and install required tooling.
- **CI Validation** (`git push / pull request`): Pre-commit and GitHub Actions enforce Terraform formatting on commits and pull requests.

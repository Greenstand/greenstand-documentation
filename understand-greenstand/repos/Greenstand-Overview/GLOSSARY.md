## Domains

### Contributor Onboarding & Development Workflow

Documentation-described process for how a new contributor learns about the Treetracker platform, finds a repo to work on, and submits code using BDD and Git fork-and-pull conventions. No code implements this; it is narrated across README.md, BDD-GUIDE.md, and the Github Basics guide.

**Terms:** Contributor, Feature file, Pull request, Repository

**Rules:**

- New work should be described as a Gherkin feature file before step definitions are written.
- Changes are proposed via fork-and-pull rather than direct pushes to upstream repos.

**Flows:**

- **Project Onboarding** (`README.md`): How a newcomer reads the README to understand the Treetracker platform's components (Android app, admin client, web map, wallet API) and finds where to plug in.
- **BDD Feature Development** (`BDD-GUIDE.md`): The documented Gherkin/Cucumber/WebdriverIO workflow: write a feature file, implement step definitions, run tests locally, and prepare a PR using the checklist.
- **GitHub Fork-and-Pull Contribution** (`Resrouces/Github Basics`): The documented Git workflow contributors follow to fork a Treetracker repo, make changes on a branch, and submit a pull request.

### Governance & Legal

Documentation-described nonprofit governance and legal framework: corporate bylaws, community team roles, code of conduct, and licensing. Describes how the organization and its contributors are structured and expected to behave, not code logic.

**Terms:** Board of Directors, Officer, Community role, Code of Conduct, AGPL-3.0 License

**Rules:**

- Corporate governance is defined by the bylaws document.
- All contributors are bound by the Contributor Covenant Code of Conduct.
- Project code is licensed under AGPL-3.0.

**Flows:**

- **Nonprofit Governance Structure** (`Greenstand-Bilaws.md`): How the organization's legal bylaws define board/officer roles, and how TEAM.md maps those to community/engineering roles.
- **Code of Conduct Enforcement** (`License, Code of Conduct etc/CODE_OF_CONDUCT.md`): The documented expectations, reporting path, and enforcement approach for community behavior, per the Contributor Covenant.

### Token Economy (Greenstand Token)

Documentation-described concept for an NFT/fungible token framework linking digital tokens to real-world environmental assets (trees), covering token states, creation, verification, and trading. This is a whitepaper concept described in Greenstand-Token.md, not an implemented system in this repo.

**Terms:** Token, Environmental asset, Token state, Node network

**Rules:**

- A token is linked to a specific environmental asset (e.g., a planted tree).
- Tokens move through defined states from creation to trade to retirement.
- Token authenticity is verified through a distributed node network.

**Flows:**

- **Token Creation and Verification** (`Greenstand-Token.md`): The whitepaper-described lifecycle of linking a token to an environmental asset, minting it, assigning it a state, and verifying it through the node network.
- **Token Trading Lifecycle** (`Greenstand-Token.md`): The whitepaper-described process of listing a verified token for trade, transacting an ownership transfer, and settling the updated state across the node network.

### Product Strategy & Planning

Documentation-described process for how the Treetracker ecosystem plans and tracks feature work: a tiered deliverables roadmap and a cross-repo issue index that contributors use to find work.

**Terms:** Roadmap tier, Deliverable, GitHub issue, Repository

**Rules:**

- Deliverables are organized into tiers of increasing scope/maturity.
- The token economy is one of the strategic roadmap items.

**Flows:**

- **Roadmap Planning** (`Roadmap.md`): How feature work is organized into tiered deliverables and prioritized, including strategic items like the token economy.
- **Issue Tracking Navigation** (`Issues-lndex.md`): How a contributor uses the cross-repo issue index to find a repository and an issue to work on.

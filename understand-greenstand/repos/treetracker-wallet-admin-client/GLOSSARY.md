## Domains

### Authentication & Access

Controls who can use the admin panel. Handles the login form, credential validation, JWT token persistence, route protection and session expiry, including automatic redirect on unauthorized API responses.

**Terms:** Credentials, AuthToken (JWT), Wallet identity, API key

**Rules:**

- Wallet name, password and API key are all required to log in
- Token and current wallet persist in localStorage; API key uses secure storage
- Protected routes render only when a valid session exists
- A 401 response clears the session and redirects to login

**Flows:**

- **User Login** (`/login`): Owner enters wallet, password and API key, the form validates each field, and valid credentials authenticate against the wallet API and open a protected session.
- **Logout & Session Expiry** (`TopMenu logout / 401 interceptor`): Owner logs out from the top menu, or an unauthorized API response ends the session; the token clears and the app redirects to login.

### Wallet Management

Lists the owner's wallets, opens a single wallet's detail view with token and pending-transfer stats, and creates new managed (sub) wallets. Wallets are the core account entity that all other domains act upon.

**Terms:** Wallet, Managed wallet, Wallet balance, Pending transfer count

**Rules:**

- A wallet list is paginated, sorted and scoped to the owner
- A new managed wallet name must pass client-side validation and be unique
- A wallet detail view combines the wallet record with its pending transfers

**Flows:**

- **Browse My Wallets** (`/wallets`): Loads the owner's wallets from the API, formats them into rows, and renders a paginated, sortable table.
- **View Wallet Details** (`/wallet/:id`): Loads a single wallet by id together with its pending transfers and renders the wallet header and information blocks.
- **Create Managed Wallet** (`Create wallet dialog`): Owner opens the create dialog, enters and validates a wallet name, submits it to the API, and sees success or error feedback.

### Token Transfers

Moves tokens between wallets and manages the resulting transfer records. Covers sending tokens to trusted and untrusted wallets with amount validation and confirmation, plus listing, filtering, accepting, declining and cancelling transfers.

**Terms:** Transfer, Pending transfer, Token amount, Sender wallet, Receiver wallet

**Rules:**

- Available tokens equal in-wallet balance minus pending transfers
- A transfer amount must be a positive number within the available balance
- Sending to a trusted wallet completes directly; sending to an untrusted wallet creates a pending transfer
- Only the receiver may accept or decline a pending transfer; only the sender may cancel it

**Flows:**

- **Send Tokens** (`/send-tokens`): Owner selects sender and receiver wallets, reviews available tokens, enters and validates an amount, confirms, and the transfer posts to the trusted or untrusted endpoint.
- **Manage Transfers** (`/transfers`): Owner loads the transfers list, filters by status and date, opens a transfer in the side panel, and accepts, declines or cancels it before the list refreshes.

### Trust Relationships

Establishes and manages trust links between wallets that permit direct token transfers. Handles requesting a new relationship, listing and filtering relationships, and accepting, declining or deleting them.

**Terms:** Trust relationship, Relationship request, Relationship type, Trusted wallet

**Rules:**

- A relationship is created between a source and target wallet with a chosen relationship type
- A requested relationship stays pending until the counterparty accepts or declines it
- Either party may delete an existing relationship

**Flows:**

- **Request Trust Relationship** (`New relationship dialog`): Owner opens the create dialog, selects the two wallets and a relationship type, submits the request, and sees success or error feedback.
- **Manage Trust Relationships** (`/trust-relationships`): Owner loads relationships, filters them, opens one in the side panel, and accepts, declines or deletes it before the list refreshes.

### Wallet Customization

Lets an owner edit a wallet's public profile: display name, about text, logo and hero image. Validates image uploads and persists the changes to the wallet record.

**Terms:** Wallet profile, Display name, About text, Logo image, Hero image

**Rules:**

- Uploaded images must pass type and size validation before save
- Profile changes save through a multipart wallet update

**Flows:**

- **Customize Wallet Appearance** (`Customize wallet page`): Owner edits display name and about text, uploads and validates logo and hero images, and saves the profile through a wallet update.

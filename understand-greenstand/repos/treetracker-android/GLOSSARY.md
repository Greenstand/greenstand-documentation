## Domains

### Tree Capture

Covers the core field work of a grower. A grower runs the org-configured capture setup, opens a capture session, and photographs each tree after the GPS position converges. The grower then reviews and annotates the capture, and the app saves it offline. This domain also restores a capture that Android interrupted, and lets growers edit or delete saved trees before upload.

**Terms:** Tree, Tree capture, Session, Location, Tree attribute, GPS convergence, Capture setup, Unsaved tree, Tree note

**Rules:**

- The capture screen accepts a photo only after the location pin is complete. The screen waits up to 30 seconds for the pin. When the wait times out or no coordinate is available, the screen shows a bad GPS dialog.
- GPS converges when the longitude and latitude standard deviations of a sliding window of GPS fixes are both below the configured thresholds.
- When the convergence wait times out, the capture uses the last converged window of the session. When no window converged, the capture uses the current window.
- Each tree belongs to the current session. A session starts when the setup flow of the organization ends. The session ends when the grower leaves capture for the dashboard or for user select.
- Each tree records the absolute step count and the delta step count as attributes. When the device gives a rotation matrix snapshot, the tree also records the snapshot.
- When the organization turns on the force note feature for image review, Next opens the note dialog while the note is blank.
- The app keeps the unsaved tree as JSON in preferences until it saves or discards the tree. Thus image review and tree height can show the tree again after Android kills the app process.
- Tree Edit lets the grower change the note or delete the tree only while the tree is not uploaded. A deletion needs a confirmation. A deletion also removes the local photo.
- In the debug, dev and beta builds, the capture screen has a button that creates fake trees. The fake trees go into the normal upload queue.

**Flows:**

- **Start Capture Session** (`Track button on the dashboard (UserSelectRoute)`): Takes a grower from the Track button through the org-configured setup steps to an open capture session with sensors and GPS running.
- **Capture Tree Photo with Converged GPS** (`Capture button on the tree capture screen (TreeCaptureRoute)`): Pins a converged GPS location for a new tree, accepts the photo only when a coordinate is known, and builds the tree record with sensor attributes.
- **Review, Annotate and Save Tree** (`Org capture flow steps after the photo (TreeImageReviewRoute, TreeHeightScreenRoute)`): Walks the org-configured capture steps after the photo, such as image review with a note and tree height, then saves the tree and loops back to capture; leaving capture ends the session.
- **Restore Interrupted Capture** (`Navigation 3 restores a setup or capture screen after process death`): Brings a capture setup step or a capture step back after Android kills the app: it reloads the kept tree and setup grower, resumes the interrupted session, or sends the grower to the dashboard when nothing can be restored.
- **Edit Saved Trees** (`Settings, Edit trees entry (TreeEditUserSelectRoute)`): Lets a grower open the trees captured under a wallet, change the note of a tree, or delete a tree and its photo while the tree is not uploaded.

### Grower Onboarding & Identity

Covers how grower accounts start and change on the device. It handles the first launch with permissions and a language choice, and sign-up with a phone or email wallet, names, and a selfie. It also covers profile viewing, editing and deletion; the first account on a device becomes the power user.

**Terms:** Grower, Wallet, Power user, Selfie, Profile, Language

**Rules:**

- The wallet of a grower is the phone number or the email that the grower enters at sign-up. When that wallet already exists on the device, sign-up offers the existing grower instead of a new account.
- Sign-up accepts an email wallet when the text contains '@'. Sign-up does no other email check.
- Sign-up accepts a phone wallet of 7 to 15 digits with no other characters.
- The first name and the last name must pass name validation before the selfie step. A valid name has 2 to 50 letters, spaces, hyphens or apostrophes.
- The app creates the account only after the selfie returns a photo path.
- When the device has no power user, the next grower from sign-up becomes the power user. The app never sets a second power user.
- A profile edit saves only the names and the photo. The wallet, the phone and the email stay as registered. The names must pass name validation before the save.
- A new profile photo clears the photo URL. Each profile edit resets the uploaded flag, so the registration uploads again.
- A profile deletion removes the local account. It also queues a deletion request message to the admin. When the deleted account is the power user, the app returns to sign-up.
- The Delete account entry of Settings shows only in the debug and dev builds.
- The app supports three languages: English, Swahili and Portuguese.

**Flows:**

- **First Launch Bootstrap** (`App launch (SplashRoute)`): Asks for runtime permissions, prepares device and org state, and sends a device without a power user to the language picker and sign-up, or a set-up device to the dashboard.
- **Grower Sign-Up** (`Sign-up flow (SignupFlowRoute) after the language picker, or the add button of the user picker`): Registers a grower with a phone or email wallet, first and last names, and a selfie, and makes the first account on the device its power user.
- **Edit Grower Profile** (`Settings, Profile entry (ProfileSelectRoute)`): Lets a grower open a profile from Settings, change the names or photo, and save the change so the registration uploads again.
- **Delete Grower Profile** (`Settings, Delete account entry (DeleteProfileRoute), debug builds only`): Deletes a grower account from the device after a confirmation and asks the admin, through a message, to delete the account data.

### Organization & Wallet Selection

Decides which organization the device works for and how its capture runs. An org link from a deep link or the Play install referrer adds the org with the setup and capture steps from Firebase Remote Config. During capture setup the grower can pick or type a destination wallet, which the session row does not use, and enter the organization name that the session row stores.

**Terms:** Organization, Wallet, Destination wallet, Grower, Org link, Capture setup, Setup flow, Capture flow, Organization override

**Rules:**

- The default Greenstand organization always exists. Its setup flow is user select and then add organization. Its capture flow is capture and then image review.
- When the app starts without an organization deep link, it reads the Play install referrer. It reads the referrer at each start until the answer is available or unsupported. Then it marks the referrer as consumed.
- The app fetches the Remote Config of a linked organization for up to 10 seconds. With a valid config, the app adds the organization with the steps of that config. Without a valid config, the app adds a minimal organization with user select as its only setup step. In both cases, the app makes it the current organization.
- Before the app stores an organization from Remote Config, it drops the routes that the route registry does not know.
- The developer options overrides apply to the current organization only in the debug and dev builds. Their master switch must also be on.
- The beta build shows the overrides in developer options. The beta build does not apply them.
- Wallet select appears only when the setup flow of the organization lists it. Wallet select and add wallet write the destination wallet into the capture setup.
- The session row takes its destination wallet from the wallet of the session grower. The session row does not use the wallet from wallet select or the wallet ID of the organization.
- The session row stores the organization name from the add organization step. When the setup flow has no add organization step, the session row stores the name of the current organization.
- The organization picker screen has a route. No screen opens it, because its dashboard button is commented out.

**Flows:**

- **Join Organization from Org Link** (`Deep link app://mobile.treetracker.org/org?id=...&name=..., or the Play install referrer at first launch`): Reads an org id and name from a deep link or the Play install referrer, fetches the org config, and stores and selects the org with its configured flows.
- **Apply Org Flow Configuration** (`App start (Root gate) and each new capture setup or capture flow scope`): Turns the stored org into the ordered setup and capture steps and the per-step features that the capture flows run.
- **Select Destination Wallet** (`Wallet select step of the org setup flow (WalletSelectRoute), and its add wallet screen`): In an org setup flow that lists wallet select, the grower picks the wallet of a grower on the device or types a new wallet name. The choice goes only into the setup data and the crash report data: the session row that setup creates takes the planting grower's wallet as its destination wallet.
- **Enter Session Organization** (`Add org step of the org setup flow (AddOrgRoute)`): In the add org setup step, the grower types an organization name or reuses the previous one, and the session row records it.

### Data Sync & Upload

Moves the offline data from the device to the backend when the grower taps upload. A foreground WorkManager job syncs messages, device config, growers, sessions, legacy trees, current trees and GPS tracks in a fixed order. Photos go to object storage first, then JSON bundles carry their URLs; the app flags uploaded rows and deletes the local photos.

**Terms:** Upload bundle, Tree, Legacy tree, Session, GPS track, Location, Device configuration, Wallet registration, Photo

**Rules:**

- The sync runs as unique work. A tap on Upload while the sync runs cancels the sync.
- When no tree waits for upload, a tap on Upload shows a message and does not start the sync. The debug and dev builds start the sync anyway.
- The upload order is fixed: messages, device configurations, growers, sessions, legacy trees, trees, and then locations.
- Trees upload in windows of 50. In each window, the photos without a URL upload first. A window fails when a photo upload returns no URL.
- When a tree that the pass tried is still not uploaded, the tree step fails. The next sync tries the remaining trees again.
- The app deletes the local tree photos after their bundle uploads.
- A grower registration needs a photo URL. When a grower photo does not upload, the grower step fails and the sync stops.
- GPS track points upload in groups by session UUID. The app purges the points after the upload.
- The app saves a new device configuration row when the app version, the app build, the OS release or the SDK level differs from the latest row.
- A sync step that throws an error stops the sync. The job then fails. The location step catches its own errors. Thus a failed track upload keeps the points for the next sync.
- The V2 captures bundle sends the step counts, the rotation matrix and the extra attributes as null. Thus the sensor attributes that capture records stay on the device.

**Flows:**

- **Run Data Sync** (`Upload button on the dashboard (DashboardAction.Sync)`): Starts or cancels the sync job from the dashboard, runs every upload step in order in a foreground job, and reports progress and the result.
- **Upload Trees and Photos** (`TREES step of the sync job`): Uploads the current trees in passes and windows: photos to the images bucket first, then a V2 captures bundle, then it deletes the local photos.
- **Upload Device Config, Growers and Sessions** (`DEVICE_CONFIG, USERS and SESSIONS steps of the sync job`): Uploads the device config rows, the grower photos and wallet registrations, and the session metadata as V2 bundles before the trees upload.
- **Record and Upload GPS Tracks** (`LOCATIONS step of the sync job; recording runs on each GPS fix during a session`): Records each GPS fix during a session as a track point, then uploads the points not yet uploaded, grouped by session, as a tracks bundle and purges them. An upload error is logged and the points stay for the next sync; the sync job does not fail.
- **Upload Legacy V1 Captures** (`USERS and LEGACY_TREES steps of the sync job`): Uploads the data that remains in the legacy V1 schema: planter check-in photos, planter registrations and legacy tree captures as V1 bundles.

### Grower Messaging

Gives each grower an inbox of direct messages, announcements and surveys from the messaging endpoint of the backend API, stored on the device per wallet. Growers chat, read announcements and answer surveys. Outgoing messages and survey answers queue on the device and upload as bundles at the end of each message sync.

**Terms:** Message, Direct message, Announcement, Survey, Question, Survey response, Inbox, Wallet

**Rules:**

- Message sync fetches the messages of each grower wallet on the device. For each wallet, it fetches only the messages after the newest stored message.
- Message sync treats a 404 answer as a wallet with no messages. An error for one wallet does not stop the fetch for the other wallets.
- Message sync ignores the survey responses that come from the server.
- The inbox shows the newest direct message from each other sender, the surveys that are not complete, and all announcements. The inbox sorts them by compose time, newest first.
- When the grower opens a chat, an announcement or a survey, the app marks it as read.
- When the grower answers the last survey question, the app saves all answers as one response linked to the survey. Then the app marks the survey complete.
- After the fetch, message sync uploads the queued outgoing messages and survey responses. They upload in groups of 50 as V2 message bundles.
- The splash and the dashboard Messages button sync messages only when the internet check succeeds.

**Flows:**

- **Sync Messages** (`Messages button on the dashboard, the splash bootstrap, and the first step of the sync job`): Downloads new messages, surveys and questions for every local wallet and uploads the queued outgoing messages and survey answers.
- **Browse Grower Inbox** (`Messages button on the dashboard (MessagesUserSelectRoute)`): Lets a grower pick a profile with unread badges and see an inbox of chats, open surveys and announcements.
- **Direct Message Chat** (`Direct message item in the inbox (chat route)`): Shows the conversation between a grower and one other party, marks it read, and queues the messages the grower sends.
- **Read Announcement** (`Announcement item in the inbox (announcement route)`): Shows one announcement with its sender, title, body and optional link, and marks it read.
- **Answer Survey** (`Survey item in the inbox (survey route)`): Takes a grower through the questions of a survey one at a time and saves the answers as a survey response for upload.

### Dashboard, Map & App Settings

The home dashboard shows the synced and pending tree counts, an upload gauge, and the buttons for upload, messages and tracking. Settings opens profiles, tree editing, the privacy policy, and in some builds the tree map, logout and account deletion. The top bar changes the app language, and debug and beta builds offer developer options.

**Terms:** Dashboard, Tree map marker, GPS track, Sync progress, Settings, Language, Developer options

**Rules:**

- The synced count and the pending count each add legacy trees and current trees. A tree counts as synced when its photo has a URL.
- When 2000 or more trees wait for upload, the Track button first shows an upload reminder.
- The dashboard stops GPS updates when it opens.
- The Map entry of Settings shows only in the debug, dev and beta builds.
- The map shows the trees of the current tree table, not legacy trees. The map also shows up to 5000 of the newest GPS points from sessions that have trees.
- The Logout and Delete account entries of Settings show only in the debug and dev builds.
- Logout removes the power user flag and returns the app to sign-up.
- A long press on the top bar logo opens developer options in the debug, dev and beta builds. The convergence parameters refresh when developer options close.
- The sync and sensor overlays show only in the debug and dev builds.
- The dashboard computes whether more than one organization exists. No screen uses that value, because the organization button of the dashboard is commented out.

**Flows:**

- **View Dashboard** (`Dashboard after the splash or sign-up (DashboardRoute)`): Shows the tree counts and upload gauge, the unread message badge, and routes the dashboard buttons to upload, messages, settings and tracking.
- **View Tree Map** (`Settings, Map entry (MapRoute), debug and beta builds only`): Shows each tree of the current schema as a map marker, with the GPS points of its session that are still on the device, and a card carousel of the trees.
- **Manage App Settings** (`Settings icon on the dashboard (SettingsRoute)`): Lists the settings entries for the build type, opens their screens, shows the privacy policy, and logs out the power user.
- **Change App Language** (`Language button in the top bar (LanguageRoute with isFromTopBar = true)`): Lets the grower switch the app language from the top bar and applies the locale at once.
- **Tune Developer Options** (`Long press on the top bar logo (DevOptionsRoute), debug and beta builds only`): Lets testers change stored config values such as GPS convergence thresholds and override the steps, features and wallet of the current org.

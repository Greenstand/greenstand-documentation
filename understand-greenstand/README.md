# understand-greenstand

Machine-generated documentation for the core-active Greenstand repository estate. It lives in the
folder `understand-greenstand/` of this repo,
[Greenstand/greenstand-documentation](https://github.com/Greenstand/greenstand-documentation).

**New volunteer?** Read [How to contribute to Greenstand](./docs/contribute-to-greenstand.md):
how to join the community, pick a first task, and get help.

## Explore the viewers

**[Open the live site → https://greenstand.github.io/greenstand-documentation/](https://greenstand.github.io/greenstand-documentation/)**

The landing page indexes every documented repo by area, like the index below. Each one has an
interactive knowledge-graph viewer (structural + domain views, a guided tour, and inline source
loaded from GitHub) plus a rendered onboarding guide, glossary, and README.

The [estate glossary](GLOSSARY.md) lists the business terms of all repos and the shared
resources, A to Z. It links each term to the repos and domains that use it, and each shared
resource to its section of the shared-resource page.

[The journey of a capture](./docs/capture-journey.md) follows one capture from the grower's phone
to the grower's reward, step by step, with pictures.

The [ecosystem maps](./ARCHITECTURE.md) show how the code repos work together at run time:
capture and verification, the web map, the wallet, the shared database, and the platform.

The [shared-resource page](./docs/shared-resources.md) shows what the code repos share to build,
deploy, and run, for example the container registry, the clusters, and the shared database.

The [contributors page](https://greenstand.github.io/greenstand-documentation/contributors.html)
thanks the people who contributed to the public Greenstand repos this quarter. It is on the live
site only.

Each source repo also has one directory under [`repos/`](./repos/). A directory holds that
repo's `knowledge-graph.json` plus rendered domain and onboarding markdown, produced by
the [Understand-Anything](https://github.com/Egonex-AI/Understand-Anything) skill suite
(`understand`, `understand-domain`, `understand-onboard`). Its `GLOSSARY.md` is generated from
the domain graph.

The layout is regenerate-ready. See [`docs/regenerating.md`](./docs/regenerating.md) for how to
regenerate a repo's docs, and [when](./docs/regenerating.md#when-to-regenerate): a weekly drift
report lists the repos that are due, and the shared-resource facts and capture journey facts to
check.

To report a problem in these docs or to change them, read [`CONTRIBUTING.md`](./CONTRIBUTING.md).
Before you push, read [`docs/private-names.md`](./docs/private-names.md): names of private
Greenstand repos must not appear here, and a `pre-push` hook and CI checks enforce that.

## Repository index

The repos are grouped by area. For each repo:

- **Viewer** opens the interactive knowledge graph on the live site.
- **Onboarding** is the generated onboarding guide.
- **Glossary** lists the business terms of the repo by domain, with the rules and flows of each
  domain.
- **README** is the summary of that repo's docs.
- **Source** is the Greenstand source repo.
- **Snapshot** is the date of the docs and the source commit that they describe. The source
  repo can have newer commits. See
  [When to regenerate](./docs/regenerating.md#when-to-regenerate).

## Scope

The estate covers 14 documented code repositories: the core Tree Tracker services, the wallet
stack, the admin tools, the web map, the mobile app, the data-ingest services, and the
infrastructure repo, plus the `treetracker-tile-server` fork (included by request). It also
covers one docs repo, `Greenstand-Overview`, in the Organization area. Other fork repos, private
repos, other docs repos, and dormant repos are out of scope.
